# Folio 제품 전체 리서치와 적용 전략

2026-11-16 · 기준: origin/main `3a2650015cf738bd26861852de7424fa0395171c` / 배포 v0.3.0. 이 문서는 조사와 적용 방향을 기록합니다. 배포 검증 결과는 릴리스 노트와 검증 문서에 별도로 기록합니다.

## 먼저 바꿀 접근

기존에는 빈 공간을 채울 이미지를 만든 뒤, 이미지를 넣을 상자와 옆의 폼을 만들었습니다. 이번에는 방문 목적 → 정보의 우선순위 → 화면의 구성 → 필요한 에셋 순서로 진행합니다.

‘모든 카드를 없앤다’는 규칙도 적절하지 않습니다. 파일 브라우저의 개별 작업물과 공유 범위를 고르는 컨트롤은 경계가 의미를 갖습니다. 반면 브랜드 일러스트와 설정 항목 전체를 각각 상자에 넣을 이유는 따로 검토해야 합니다.

## 랜딩과 로그인은 같은 배치를 사용하지 않는다

로그인 화면 6개도 따로 확인했습니다. 외부 제품의 인증·계정 생성·동의 동작은 수행하지 않았습니다.

- [Craft 로그인](https://docs.craft.do/): 중앙 폼은 작고 명확하게 유지하면서 구름이 전체 배경을 사용합니다. 랜딩의 재질은 이어지지만 랜딩의 많은 정보는 가져오지 않습니다.
- [Resend 로그인](https://resend.com/login): 폼 바깥의 큰 곡면이 화면 가장자리에서 잘리며 공간을 만듭니다. 이미지에 별도 카드가 없습니다.
- [Linear 로그인](https://linear.app/login), [Framer 로그인](https://framer.com/login): 상징과 로그인 동작만 남긴 집중형 진입 화면입니다.
- [Pitch 로그인](https://app.pitch.com/?login=true): 중앙 폼과 브랜드 배경을 사용합니다. CAPTCHA가 보이는 상태까지 관찰했고 인증을 진행하지 않았습니다.
- [Raycast 로그인](https://www.raycast.com/users/sign_in): 랜딩의 브랜드 색과 로고를 유지하는 단일 로그인 영역입니다.



## Folio의 에셋을 준비하는 원칙

| 역할 | 준비할 재료 | 배치 원칙 |
|---|---|---|
| 제품 증거 | 실제 렌더링한 HTML 문서, 차트, 프로토타입, 공개 아티팩트 | 핵심 내용이 읽히는 크기. 페이지의 여백·경계·겹침을 먼저 설계하고 필요한 크기로 촬영 |
| 브랜드 재료 | Folio의 접힌 모서리와 파란색을 확장한 소수의 독립 오브젝트/배경 재료 | 투명 배경 또는 페이지 배경과 자연스럽게 이어지는 형태. 한 직사각형 이미지를 모든 슬롯에 재사용하지 않음 |
| 상태 안내 | 업로드 전, 검색 결과 없음, 공유함 비어 있음, 보관함 비어 있음의 작은 시각 요소 | 상태를 설명하고 다음 행동을 안내. 사용자가 작업하는 영역을 크게 점유하지 않음 |
| 업무 UI | 파일 항목, 표, 입력 필드, 상태, 도구 연결 | 의미 있는 항목에만 경계 사용. 관리자 화면의 빈 공간을 장식 이미지로 채우지 않음 |

### 제작 순서

1. 제품 전체의 업무 흐름과 현재 문제를 실제 화면으로 확인한다.
2. 로그인 / 라이브러리 / 보기·공유 / 관리자 설정의 역할을 따로 정의한다.
3. 각 역할에 맞는 구도와 정보 우선순위를 먼저 정한다.
4. 그 구도가 요구하는 실제 제품 캡처와 독립 에셋을 준비한다. 이미지 생성은 이 시점에 수행한다.
5. 공유하는 타이포·색·간격·상태·내비게이션 원칙으로 전체 화면을 연결한다.
6. 대표 화면의 데스크톱·모바일을 함께 확인한 뒤 범위를 넓힌다.

외부 제품의 캡처는 비공개 조사 자료이며, Folio의 MIT 배포 에셋으로 포함하지 않습니다.

## Folio 전체 화면에서 확인한 문제

실제 v0.3.0을 임시 로컬 설치하고 자체 제작 HTML 작업물로 24개 상태(데스크톱 17, 모바일 7)를 확인했습니다. 제품 데이터와 외부 연결을 수정하지 않았습니다. 세부 캡처와 측정은 저장소에 배포하지 않는 로컬 조사 자료로 보관합니다. 업무 화면은 아래 공식 문서의 공개 UI 자료를 함께 확인했습니다.

| 우선순위 | 실제 확인 | 적용 방향 |
|---|---|---|
| 1 | 모바일 구성원: 390px 뷰포트에서 문서 폭 약 560px. 관리 동작이 오른쪽으로 밀림 | 모바일 행은 신원·상태·관리가 함께 보이게 재구성하고 문서 넘침 제거 |
| 2 | 같은 작업물의 렌더링 폭이 그리드 1349px → 목록 392px로 바뀌어 목록에서 내용이 다르게 접히고 잘림 | 인식용 썸네일과 실제 열람 화면을 분리. 썸네일 구도는 안정적으로 유지 |
| 3 | 모바일 상세는 작업물이 353×243px 안에 절반 비율로 들어가고 나머지가 메타정보 중심 | 열람 캔버스를 주영역으로, 버전·관리·공유는 보조 영역으로 배치 |
| 4 | 모바일 저장소 설명이 약 77px 폭의 세로 기둥으로 눌림 | 수치·미터·정책 설명이 가로 폭을 사용할 수 있도록 재배치 |
| 5 | 작업물마다 바깥 카드·안쪽 프레임·설명·작성자·권한·날짜·용량·분할 버튼이 반복 | 실제 미리보기와 제목·권한을 우선. 보조 행동과 세부정보는 맥락 안에 배치 |
| 6 | 에이전트 두 열이 같은 높이로 강제되어 토큰 쪽이 비고 코드 쪽은 좁음 | 연결 순서를 따르는 구성. 코드와 토큰 목록은 필요한 너비로 사용 |
| 7 | 도메인 첫 빈 상태가 큰 공간을 차지하고 선택적 연결 설정이 길게 노출 | 연결 상태와 다음 행동을 먼저, 선택한 연결 방법에 맞는 설정을 펼침 |
| 8 | 조직 설정에 설치 참고정보와 선택적 Google 설정의 많은 설명이 같은 강도로 나열 | 일반 정보·인증 설정·설치 참고정보에 서로 다른 위계 부여 |

### 적용 범위와 보존할 것

사용자는 이번 범위를 **Folio 제품 전체 UI 개선**으로 확정했습니다. 로그인, 라이브러리(개인·조직·보관함), 목록, 상세 보기·버전, 공유 사이드 패널, 게시, 구성원, 저장소·보관, 도메인, 에이전트, 조직·Google 설정과 계정 화면이 대상입니다.

Folio 이름과 접힌 모서리 마크, 밝은 중립색과 파란색의 기존 B 방향은 이어갑니다. 각 화면은 업무에 맞는 구성을 사용합니다. 인증·권한·아티팩트 실행 도메인 분리·실제 API·비밀 키·기존 사용자 데이터·오프라인 핵심 동작은 디자인 변경으로 바꾸지 않습니다.

### 이번 패스의 제작 순서

1. 라이브러리의 구도가 서로 다른 시안을 비교해 제품 내부의 기준을 정한다.
2. 로그인은 그 기준의 색·타이포·재료를 공유하되 로그인 업무에 맞게 따로 구성한다.
3. 보기·공유는 작업물을 중심으로, 관리자는 읽기 쉬운 행과 단계로 확장한다.
4. 이 구도에 필요한 실제 결과물 촬영과 독립 브랜드 에셋을 만든다.
5. 전체 화면의 반응형·내용 범위·오류·빈 상태를 확인하고, 기존 기능 회귀 검증 후 배포한다.

시안은 실제 배포 화면으로 표기하지 않으며, 레퍼런스 브랜드의 에셋은 제품 안에 넣지 않습니다.

## 선택한 구성과 실제 제품에 맞춘 수정

사용자가 시안 선택부터 적용·검증·배포까지 자율 진행을 요청했습니다. 네 라이브러리 시안 중 큰 작업물 미리보기와 간결한 작성자·권한 행을 가진 D를 선택했습니다. 그 구도에서 로그인·열람·공유·관리 화면을 확장했으며, 시안과 HTML 변환 자료는 비공개 조사 폴더에 보관합니다.

생성 시안의 잘못된 제품 정보는 구현하지 않았습니다. 로그인에 인증된 조직 내비게이션을 노출하지 않으며, 기억하기·비밀번호 재설정·추천 작업물·가짜 로그인 시각을 추가하지 않습니다. 보관함 자동 삭제와 고정된 수정 불가 용량도 실제 정책과 달라 제외했습니다. 공개 링크와 조직 공유의 아이콘·라벨은 실제 권한에 맞춥니다. 공유는 기존 사이드 패널을 유지합니다.

12ui는 추가 화면 두 개를 만들기 전에 생성 한도에 도달했습니다. 추가 결제 없이 확보한 여섯 화면과 공통 시각 원칙을 사용했습니다. 작업물은 생성 이미지로 대체하지 않고 실제 격리된 실행 도메인의 iframe으로 표시합니다. 변환 HTML의 원격 폰트 의존성과 고정 좌표 방식은 기존 오프라인 React 앱의 내장 폰트·반응형 컴포넌트로 통합합니다.
