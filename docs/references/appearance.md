# Appearance, controls and contrast references

The v0.6 interface extends the approved Workspace B composition with system/light/dark appearance, a shared Select, recognizable integration marks and local profile photos. Its colors are measured in the rendered application, not accepted from a palette generator alone.

## Standards and implementation

- [WCAG 2.2, 1.4.3 Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): 4.5:1 for ordinary text, 3:1 for large text. [Google Material typography guidance](https://m3.material.io/styles/typography/applying-type) also directs designers to accessible text/background contrast. Folio retains its own brand and layout rather than adopting a different visual identity.
- [WCAG 2.2, 1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html): information needed to identify controls and states needs 3:1 against adjacent colors. Disabled controls and decorative graphics have different requirements. Labels, checkmarks and readable state text accompany color; purely decorative divider strokes are not treated as field boundaries.
- [MDN color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme) and [matchMedia](https://developer.mozilla.org/en-US/docs/Web/API/Window/matchMedia): `web/public/theme.js` sets the resolved theme before React starts, observes system changes, retains explicit preference, synchronizes tabs and handles denied storage. `web/src/Theme.css` supplies the semantic palette and native control scheme. Uploaded artifact frames keep their own colors.
- [Radix Select](https://www.radix-ui.com/primitives/docs/components/select) and [Radix accessibility](https://www.radix-ui.com/primitives/docs/overview/accessibility): `@radix-ui/react-select@2.4.1` provides the actual trigger/listbox, focus, keyboard navigation, typeahead, disabled items and popup positioning. Its installed `dist/index.d.ts` and implementation were inspected. `web/src/Select.tsx` supplies Folio labels/service marks and `Select.css` styles focus, selection, scrolling, viewport limits and reduced motion. Parent modal keyboard handling defers while the Select is open.
- [HTML icon relationships](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel#icon): `web/public/brand-mark.svg` is the existing Folio silhouette. `scripts/generate-icons.sh` derives the framed SVG, multi-size ICO, Apple icon and 192/512px icons. The frame keeps the tab icon visible in either browser theme; the in-app monochrome mark uses the appropriate polarity.
- [axe-core](https://github.com/dequelabs/axe-core): pinned `axe-core@4.14.1` is a development-only test dependency, never a runtime network service. Its `RunOptions`/contrast implementation were inspected. The browser suites run actual text contrast checks, and `web/tests/contrast.js` supplements them with rendered field boundaries, placeholders, icon controls and visible keyboard focus using the WCAG relative-luminance formula.

## Decisions from measured failures

The original light palette produced 4.14:1 shortcut text, 4.43:1 status text and a 4.46:1 supporting label. Some original input boundaries measured between 1.15:1 and 1.59:1. The new palette strengthens supporting text and gives form controls their own stroke tokens. Dark mode uses a pale primary action with dark text, rather than blindly inverting every image or color. Changes to the account avatar were also checked against its actual button background.

The default follows the system. A manual choice persists locally and does not change organization settings or another user's preference. Switching palettes temporarily disables background transitions so foregrounds cannot switch before the background catches up. Logo and vendor marks preserve their identity; monochrome vendor marks use a clear plate rather than recoloring the original artwork.

The browser coverage includes authentication/errors, navigation, library/reading, review/diffs, sharing, storage/provider menus, administration, photos, guest readers and client-specific agent guides. It exercises normal/selected/focused states, disabled items, popup dismissal and focus return, photo save/reload/remove, narrow layouts and five-language controls. The verification record reports the final measured results. This focused contrast/interaction validation is not a claim of complete WCAG certification or assistive-technology coverage; uploaded documents and native OS dialogs remain separate content.
