# Folio design

## Product and authorization
Folio is a personal open-source project, MIT throughout first-party code, for teams and their agents to create and share artifacts from their own infrastructure. User chose the name Folio and asked to carry work through implementation and verification, notifying on completion. All requested scope below is required. Implementation choices are engineering rulings, not additional user requirements.

The user explicitly authorizes a new nonconflicting test subdomain of the existing Cloudflare-managed melona.cloud zone and real HTTPS/access tests. Preserve existing services and DNS. Public GitHub source and release are authorized by the request for an open-source MIT project and one-prompt distribution; never publish credentials or private runtime data.

## Required behavior
1. Installable server usable by default within a LAN, without any runtime Internet/cloud/model/email dependency. Also document air-gap installation from a prebuilt archive. Offer a single binary plus Docker. README contains one copyable prompt an agent can follow to install it.
2. Agent tools are first-class: official-SDK MCP stdio server, CLI, and portable SKILL.md. Tools discover the service and capabilities, list/find artifacts, publish a directory, update existing content, inspect versions, change sharing, archive/restore, and report limits. The existing agent chooses its own model/gateway; no model is embedded.
3. Local administrator bootstrap, no open self-registration. Admin can initially create member/admin accounts, issue temporary passwords, suspend users, reset passwords, and inspect an audit log. First-login password changes, last-admin protection and session/token revocation are required. One organization per installation, with membership controlled by the admin; multi-tenant SaaS is not part of this release.
4. Artifact library with separate My artifacts and Organization/shared-with-me collections. Private items never appear in another member's list/search. Admin can explicitly see/manage all. Search, sort, artifact details/preview, versions, new publication/update, rollback, download, archive, restore, delete.
5. Sharing is a right-side panel, keyboard accessible and responsive: Private; Organization; Specific people (active-member picker); Public link. Default private. Save the selected scope, revoke access immediately, copy a stable link, display who can access it. Recipient permissions are read-only; content owners/admins publish and manage sharing. User-specified access expiry is supported. Switching scope must atomically replace grants, not accumulate stale members.
6. Storage policies: maximum storage bytes, maximum upload bytes, retention days, overflow policy reject (default) or delete_oldest. Archive retains content and existing sharing, is hidden from active library, and is never auto-deleted. Archive data still counts toward quota. Explicit manual deletion requires confirmation. Automated cleanup must be dry-runnable, audited, deterministic oldest-first, never remove the artifact being updated, and be atomic with quota admission. If protected/archived bytes prevent freeing enough space, reject publication. Retention is based on last publication time; it cannot silently delete a newer version created concurrently.
7. Storage connections: local filesystem default; AWS S3, S3-compatible (Cloudflare R2/MinIO), Google Cloud Storage, Azure Blob. Use maintained official SDKs where applicable. Configure/test/select the default in backoffice. Credentials redacted from responses/logs and encrypted at rest with an installation key. Each version records its backend ID; changing the default affects new versions and never breaks old content. Refuse deleting a backend with referenced data. Never make buckets public; Folio serves authorized objects. Use emulators/HTTP contract tests without live cloud credentials; report live-account limits honestly.
8. Domains: automatic Cloudflare DNS and browser-login route using official cloudflared, plus API-token alternative; guided manual A/CNAME/TXT records for any DNS provider. Extensible login-provider adapter, with real Domain Connect discovery/apply flow only for providers/templates that support it; unsupported registrars get manual instructions, never fabricated OAuth support. Verify ownership/records before routing a custom domain. Domains bind an artifact; private artifacts stay private. An internal deployment does not magically become publicly reachable; show the separate ingress/origin requirement. Optional Cloudflare Tunnel public ingress must be opt-in. Existing records are never overwritten implicitly.
9. Polished modern backoffice grounded in reference products. Desktop left navigation, top search/command affordance, main artifact grid/list, right details/share drawer. Views: Library, My artifacts, Organization, Archive, Members, Storage & retention, Domains, Agents & API keys, Organization settings, Audit. Fully functional loading/empty/error/success states; mobile drawer; focus, labels and keyboard interactions. No fake statistics, fake storage health or fake successful connection state.
10. Actual public melona.cloud subdomain integration test including HTTPS, public artifact access without login, private/organization/selected-member denial, authorized access, and revocation. DNS writes limited to newly-created Folio test records.

## Chosen architecture and alternatives
- Choose Go single executable with embedded React/Vite frontend, SQLite metadata and pluggable object storage. Reason: simple offline distribution, one service, no required container daemon/database server. A Next.js/Postgres/MinIO stack adds installation dependencies; a hosted-only Worker architecture conflicts with on-prem defaults.
- HTTP API is shared by web UI, CLI, and MCP. No MCP-only privileged bypass. Tokens inherit active membership, resource permissions, expiry and revocation. Never add administrative credentials to an agent's default tool bundle.
- Path-based content on the management origin is the default mode; see `2026-11-18-path-content-design.md`. The rest of this item describes subdomain mode. Management and each artifact use distinct origins and listeners. Default management URL http://folio.localhost:4310; content URL template http://{artifact}.content.folio.localhost:4311, substituting the artifact's stable slug. Require an artifact-isolated hostname template, never a shared execution origin for different artifacts. Production wildcard DNS is operator-configured; the melona.cloud test uses explicit new artifact host records at one subdomain level so existing wildcard TLS can cover them without touching a parent wildcard. Management cookies are host-only, HttpOnly, SameSite=Lax or stricter, Secure with HTTPS. State-changing cookie requests need CSRF token AND Origin validation; bearer requests use scoped API tokens.
- Management origin never serves uploaded HTML inline (downloads attachment only). Viewer page `/s/{slug}` is a trusted wrapper. It requests a single-use, short-lived grant URL for that artifact's content origin; grant sets a host-only HttpOnly content viewer cookie and redirects to the version's content. Cookie is separate from the admin session AND bound to one artifact, destination hostname, principal and originating management session/API token. Every asset rechecks live originating credential, user/membership/scope/expiry and host/artifact binding; signed URL alone is not lasting access. Anonymous public files need no viewer cookie. View-only users cannot call mutation APIs. `/launch` can name a destination hostname only if it is the canonical host for that artifact or its verified custom domain. The nonce is bound to that exact destination. Private custom domains redirect unauthenticated users to the trusted app `/s/{slug}?domain=...` and use this same exchange; never trust an arbitrary return URL.
- Content responses enforce sandbox CSP (scripts/forms/downloads AND same-origin allowed on the per-artifact isolated host; top-navigation/popups not granted), nosniff and no-referrer, and authenticated content is no-store. Same-origin modules now use normal credentialed same-origin fetches. Parent management origin differs, so the artifact cannot remove the parent's iframe sandbox. Each host serves exactly one artifact even when a principal can read others. Content-host cookies never authorize management APIs. Tests cover ES-module and relative asset compatibility, malicious HTML fetching management or a different artifact, grant replay/host mismatch, originating-session revocation between HTML and asset, version changes and path traversal.
- Upload uses multipart JSON metadata plus numbered file parts so relative paths are not lost by Go's multipart filename normalization. Validate every path, reject traversal/symlinks/dot-secret paths, enforce expanded total size and number of files, stage blobs and atomically finalize a complete version. No partially published artifacts on failed upload.
- Public-safe example content is generated locally; no user production data copied into demos. Demo accounts exist only in development fixtures, never production/default setup.

## Quota, cleanup and failure contract
Quota measures logically retained version bytes; a separate pending-deletion byte count reports physical objects waiting for GC. First stage and verify all new blobs. Then one SQLite transaction admits the new version and tombstones any eligible quota-eviction candidates. Before that commit, no old artifact can be evicted. Failed staging/admission leaves existing publications unchanged and queues staged orphans for cleanup. Only after commit does idempotent GC delete tombstoned objects. Partial provider deletion failure stays queued with an audit/error status; it does not roll back valid new content or pretend physical bytes were reclaimed. Automatic retention uses the same transaction/tombstone/GC flow and checks the candidate's current version timestamp again. Archive, artifact-being-updated and ineligible owners are excluded. Tests inject blob-put failure, transaction failure and partial-delete failure.

## DNS login and ingress contract
Cloudflare token mode supports zone listing and collision-safe CNAME/TXT provisioning. Login mode invokes official `cloudflared tunnel login` with a dedicated certificate path, returns its official authorization URL, then tracks completion. Optional public ingress is a separate explicit action: create or select this installation's dedicated tunnel, write exact console/content/custom-host ingress rules to a private configuration, create only approved new DNS records, start the connector, and report health; stop affects only the process owned by Folio. No browser login implies a tunnel is running. API supports inspect/create/start/stop of that dedicated connector. Domain Connect discovery leads to an authorize endpoint only for configured provider/service template IDs; issue a one-use expiring state bound to admin/domain, validate the HTTPS provider destination and callback, then verify DNS before activating the domain. A provider lacking discovery/template support remains manual with exact records.

## Implementation contract
See `docs/API.md` for exact routes/JSON and package interfaces. Backend owner implements internal/server; storage provider owner implements internal/blob; agent/DNS owner implements internal/agent, internal/dns and cmd/folio plus packaging; frontend owner implements web/. Root owns integration, reference research, release and live verification. Shared go.mod changes go through the root.

## Defaults
- Bind listeners to 127.0.0.1 unless explicitly configured for LAN/proxy; Docker compose can expose host ports intentionally.
- Workspace quota 1 GiB; upload limit 128 MiB; file count 2500; no retention expiry until configured; overflow rejects; artifact default private.
- Tokens/session secrets are random 256-bit; token hashes stored, never recoverable plaintext. Password minimum 12 characters. Login rate-limited. Expiring grants no more than 60 seconds and single-use; viewer sessions bounded and revalidated per request.
- Admin cleanup run supports dry-run and explicit execution; scheduler periodically applies saved policy. Archived artifacts remain excluded. Content storage failures do not convert into metadata-only success.
- SQLite backup/restore and data-key preservation documented. No default telemetry. All frontend fonts/icons/assets included in the build.

## Acceptance and evidence
- Unit/integration tests for auth, role matrix, collection isolation, every sharing mode and expiry/revocation, upload traversal/atomicity, versions/rollback, retention/quota/archive, storage change continuity and secret redaction, Cloudflare collision/ownership validation, Domain Connect refusal/flow, MCP initialize/list/call and actual publication.
- Build Go/React, Go race suite, typecheck, production build and meaningful browser end-to-end tests across admin/member/anonymous sessions at desktop/mobile widths.
- Start from a clean temporary data directory and perform bootstrap, admin account creation, first-login change, publication, all shares, archive/restore, quota rejection/eviction and retention, storage connection tests, domain setup UI, CLI+MCP publication.
- Build release archives, install via install script to a temporary directory, run doctor and offline smoke test; Docker image startup validated.
- Verify live subdomains with actual DNS lookup and HTTPS, not only a green build or DNS API success. Save non-secret evidence in docs/verification. Cloud storage live accounts requiring credentials are distinguished from emulator/contract validation.
