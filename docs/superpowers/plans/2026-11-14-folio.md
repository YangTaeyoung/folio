# Folio Implementation Plan

**Goal:** Deliver every requested on-prem artifact publishing feature, MIT distribution, first-class agent tools, and real melona.cloud verification.
**Architecture:** Go executable embeds a React/Vite UI and serves separate management/content origins. SQLite metadata, encrypted provider credentials, local/cloud blob adapters, shared authorized HTTP API for browser/CLI/MCP.
**Spec:** ../specs/2026-11-14-folio-design.md; exact contracts ../../API.md.
**Execution:** User asked autonomous work and notification when all features are implemented, then approved Folio and told us to push forward. Resolve routine design choices and proceed; do not introduce a design or plan approval pause. Independent implementation ownership is explicit below. Use independent agent tasks only where paths/contracts prevent shared mutations; root integrates and reviews.

## Global constraints
- MIT first-party code; offline/on-prem core; no default telemetry, external fonts/CDNs, model subscription, email server, or cloud runtime requirement.
- Private-by-default sharing and authorization on every asset. Management and content origins differ; cookie/origin/CSRF boundaries tested.
- All required scope in spec is binding. No placeholder success states, no credentials in source, no implicit overwrite of existing DNS.
- Archive excludes automatic deletion; quota defaults reject; storage backend switches preserve historical version access.
- Public test DNS limited to new Folio records under melona.cloud; unrelated services preserved.

## Review focus
1. Arbitrary HTML attempting management access or stealing credentials; serve only from isolated content origin and revalidate grants/assets.
2. Revoked/suspended/expired memberships and grants between HTML and asset requests; immediate denial.
3. Failed/oversized/concurrent upload under cleanup/quota pressure; atomic metadata and bounded staged objects.
4. Archived/old-version objects during backend switching and cleanup; no unintended deletion or broken previous storage references.
5. DNS collisions, untrusted Domain Connect discovery URLs and plaintext credentials in API/list/logs; refuse or redact with evidence.
