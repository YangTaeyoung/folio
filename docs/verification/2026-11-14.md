# Folio v0.1.0 verification — 2026-11-14

This records observed behavior and the boundaries of the first release. All browser captures are from the running application with real uploaded example files. The separate design blueprint in `docs/references/` is not runtime evidence.

- Manual custom-domain experiment: `folio-preview.melona.cloud`, verified with its public ownership TXT and exact HTTPS origin challenge; authenticated custom-host ES modules load, and anonymous access redirects to the trusted access-denied page.

Observed through actual HTTPS: browser setup and publication; anonymous interactive public page; authenticated private ES modules; anonymous raw-asset denial; immediate public-to-private revocation, then restoration of the public example. A real stdio MCP client initialized protocol `2025-11-25`, listed nine tools and published a new revision through the live HTTPS API while retaining its stable share URL and metadata. CLI doctor also authenticated through HTTPS. These checks were repeated against the `v0.1.0` executable after restarting the live process; all completed without an uncaught browser error.

A further ten checks ran through the live HTTPS installation: selected-member access, unselected/anonymous denial, recipient mutation denial, search isolation, organization access for two members, suspension and revocation against existing content sessions, and sharing expiry. The test artifact was restored to private and the two newly created test members were suspended after verification.

The live server is a test process on the developer's Mac, not an always-on hosted service. The public example uses sample data from [`examples/`](../../examples/README.md). Runtime credentials, database, tokens and private test logs are excluded from Git.

## Explicit verification limits

- Cloudflare's official browser login was started, but the browser account requires the user's interactive authentication. Live DNS/HTTPS testing used the connected Cloudflare API, not a completed Folio browser-certificate login. Certificate parsing, selected-zone behavior, success, denial and sanitized error paths have source-backed integration tests.
- No real AWS, Google Cloud or Azure account was attached. GCS/Azure were tested against independent emulators plus strict request contracts; S3 was tested against HTTP contracts. These do not establish the permissions of a user's future bucket or account.
- Domain Connect needs a provider-approved template and configured provider/service IDs and HTTPS authorities. The implementation does not claim universal registrar OAuth or an approved public Folio template.
- One server owns a local data directory; a second process is rejected. SQLite data and the lock file require a filesystem with reliable SQLite locks. This is a single-node installation, not a clustered database.
- Content reads/downloads and GC serialize under the state mutex; this release is intended for small installations. Upload streaming and remote writes release the lock and revalidate before committing.
- A host has one viewer cookie. Opening different historical versions of the same artifact concurrently can replace that host's version pin; reopen the intended preview. Per-request credential and sharing checks still apply.
- The release has been validated on macOS arm64 and Linux arm64 runtimes. Windows and macOS amd64 archives were cross-built and their formats checked; no native Windows or Intel Mac runtime test is claimed.
