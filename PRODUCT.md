# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

People and their AI agents publishing interactive artifacts for a team; administrators operating their own installation. The user requested a personal open-source project rather than a subscription-bound hosted product.

## Product Purpose

Publish static HTML artifacts and related files on infrastructure the team controls, then share privately, with selected members, with the organization, or publicly.

## Operating Context

Internal-network/offline core; optional cloud object storage and public DNS/tunnel ingress. Browser backoffice, Go CLI and MCP share the same authorization-enforcing API.

## Capabilities and Constraints

Admin-created accounts, personal/team libraries, side-panel sharing and expiry, versions/rollback, archive/retention/quota, local/S3/GCS/Azure storage, Cloudflare and manual DNS. Preserve content-host isolation, permissions, token scopes, private defaults and existing retained data. Use embedded assets and fonts; no runtime CDN or model subscription.

## Brand Commitments

The user chose the name Folio and MIT licensing. On 2026-11-15 the user rejected the entire previous visual design. Sage/ivory, bookish styling, serif wordmark, tiny labels and poetic library copy are not binding brand assets. The original request explicitly asked for modern design grounded in real product references.

## Evidence on Hand

Released source and real product screenshots in docs/images; functioning public and authenticated HTTPS installation; example artifacts in examples. Reference and concept images are inspiration, not screenshots of released software. No fabricated production activity, customers, storage health or usage numbers.

## Product Principles

- Put the artifact and its access state before explanatory decoration.
- Make publishing, finding and sharing an artifact immediately understandable.
- Keep admin operations legible and consistent across screens.
- Preserve offline operation and authorization across every interface.
